# Исправления Earnline iOS · 5 сентября 2026

Версия: **1.1.1 (4)**. Продолжение `AUDIT-IOS-2026-09-05.md`.
Работа касается iOS и необходимого ему серверного протокола. Веб-клиент не изменён.

## Изменения

| Аудит | Исправление |
|---|---|
| I-01 | Создание и редактирование используют строгий денежный парсер. Текст не очищается с изменением смысла, сумма не ограничивается молча. Неоднозначные разделители, третья десятичная цифра и превышение максимума отклоняются. |
| I-02 | Пакет собирает содержимое и отметку правки одновременно. Строки, удалённые во время предыдущего запроса, пропускаются. Ответ сервера сохраняет подтверждённую версию, не снимая dirty с более поздней правки. |
| I-03 | Подготовлена атомарная серверная операция `earnline_upsert_versioned`: блокировка строки, проверка ожидаемой версии, запись и ответ в одной транзакции. Конфликт возвращается как PT409. Версии сохраняют микросекунды PostgreSQL. Требует применения миграции. |
| I-04 | Валюты и курс редактируются как отдельный черновик и применяются вместе. Перестановка пары инвертирует курс; новая пара требует своего курса. Поздний сетевой ответ проверяет пространство и версии настроек/черновика; отменённые ответы не применяются. |
| I-05 | Ограничения текста используют Unicode-коды, как PostgreSQL, включая CSV и синхронизацию значков. При ограничении ввода составной символ не разрезается. |
| I-06 | Скрипт Release проверяет HTTPS с непустым host, публичный ключ либо JWT с ролью anon. Серверные ключи и иные роли отклоняются до упаковки. |
| I-07 | Синхронизация и разрешение конфликтов доступны в обычных настройках. Ошибка синхронизации также видна в журнале. |
| I-08 | Дополнены русские подписи и сообщения восстановления, резервных копий, настроек, синхронизации и Keychain. Убрана англоязычная строка So far. |
| I-09 | Предпросмотр копии показывает исходную и текущую валютные пары и курсы. Импорт не заменяет текущие настройки автоматически. |
| I-10 | Composer и сводка используют вертикальную раскладку при размерах доступности. Заголовок заработка переносится как единая локализованная строка. Обычная сводка сохраняет ограниченную высоту. |

GitHub-вход в Release использует URL-схему, зарегистрированную в Info.plist,

Исходный основной проект найден. Подтверждены доступность Auth, включённый
GitHub, наличие GitHub-аккаунта с доступом владельца к существующему пространству

Секретные серверные ключи в приложение не добавлены.

**После явного подтверждения владельца миграция
`supabase/migrations/20260905083123_atomic_ios_sync.sql` применена сначала
к тестовому, затем к основному Supabase.** Проверены сигнатура функции,
права authenticated, запрет anon и режим security invoker. Основной REST API
распознаёт функцию: анонимный проверочный вызов возвращает отказ доступа 42501,
а не ошибку отсутствующей функции. После миграции 35 записей и 4 клиента
сохранены; контрольные суммы содержимого обеих таблиц до и после совпадают.
Повторная синхронизация с физического iPhone пока не подтверждена.

Миграция добавляет RPC и делает отметки новых изменений монотонными. Она не
переписывает существующие записи и сохраняет RLS. Старые клиенты сохраняют
свой прежний табличный API. Для отмены выпуска можно вернуть предыдущий IPA;
добавленный RPC не мешает прежнему клиенту. Самостоятельно откатывать данные
или удалять хранилища не требуется.

## Исправление повторного конфликта на iPhone

После реального входа сервер возвращал HTTP 409 на отправку локальных записей,
в том числе при выборе Keep changes from this iPhone. Воспроизведена причина:
Swift передаёт UUID с заглавными буквами, а RPC сравнивал их с PostgreSQL
uuid::text как регистрозависимый текст. Существующая строка считалась отсутствующей;
обычная запись давала ложный конфликт версии, принудительная — конфликт вставки.

Миграция `20260905145633_normalize_sync_uuid_identity.sql` нормализует только UUID
строк; текстовый идентификатор пространства остаётся регистрозависимым. Применена
к тестовому и основному Supabase в рамках разрешённого исправления синхронизации.
Новый IPA не требуется. Существующие строки миграция не меняет.

Регрессия с uppercase UUID падала до исправления и проходит после: обычное
обновление, отказ устаревшей версии и принудительный выбор локальной копии.
Полный локальный SQL-прогон проходит, включая конкурентные записи, атомарность,
удаления и ограничения доступа. В обоих облачных проектах проверены новая
функция и права доступа. Повторное нажатие на физическом iPhone ещё не проверено.
